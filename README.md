# Simple Contact — Local Network Chat (محادثة الشبكة المحلية)

مشروع جامعي تعليمي لتطبيق محادثة فورية يعمل داخل الشبكة المحلية (LAN / Wi-Fi) بالاعتماد على **Python** و **WebSocket** و **HTML/CSS/JavaScript**.

---

## 1. نظرة عامة على المشروع (Project Overview)

تطبيق **Simple Contact** يتيح للأجهزة المتصلة على نفس شبكة الـ Wi-Fi أو الكيبل (LAN) التواصل وإرسال الرسائل النصية الفورية فيما بينها بدون الحاجة إلى إنترنت خارجي وبدون أي قواعد بيانات معقدة:
- **جهاز السيرفر (Server PC):** يشغل سيرفر الويب وسيرفر المحادثة اللحظية بلغة Python.
- **أجهزة العملاء (Client PCs / Phones):** تفتح متصفح الويب للدخول إلى واجهة التطبيق، تسجيل اسم المستخدم، رؤية المتصلين، وبدء محادثة مباشرة.

---

## 2. معمارية النظام (System Architecture)

```text
               ┌──────────────────────────────┐
               │    Local Area Network (LAN)  │
               │         Wi-Fi / Router       │
               └──────────────┬───────────────┘
                              │
                              ▼
```

## 3. كيف يعمل النظام؟ (How It Works & Network Flow)

تتم دورة عمل التطبيق عبر مرحلتين أساسيتين:

### المرحلة الأولى: تحميل واجهة الويب (HTTP)
1. يفتح المتصفح الرابط `http://192.168.1.10:8000`.
2. يستقبل **Python HTTP Server** الطلب ويرسل ملفات الواجهة (`index.html`, `style.css`, `app.js`).
3. يتم بناء الواجهة في متصفح العميل.

### المرحلة الثانية: المحادثة الحية (WebSocket over TCP)
1. يدخل المستخدم اسمه (مثال: `Ahmed`) ويضغط **انضمام (Join)**.
2. ينشئ كود JavaScript اتصال WebSocket بالرابط `ws://192.168.1.10:8765`.
3. يتم إتمام **TCP 3-Way Handshake** بين جهاز العميل وجهاز السيرفر.
4. يرسل العميل رسالة انضمام بتنسيق JSON:
   ```json
   {"type": "join", "username": "Ahmed"}
   ```
5. يسجل السيرفر اتصال `Ahmed` في الذاكرة ويرسل قائمة المتصلين المحدثة لجميع الأجهزة:
   ```json
   {"type": "users", "users": ["Ahmed", "Mohammed"]}
   ```
6. عندما يرسل `Ahmed` رسالة إلى `Mohammed`:
   ```json
   {"type": "message", "to": "Mohammed", "text": "مرحباً يا محمد"}
   ```
7. يبحث السيرفر في الذاكرة عن اتصال `Mohammed` ويعيد توجيه الرسالة إليه فوراً.
8. عند الضغط على **قطع الاتصال (Disconnect)** أو إغلاق المتصفح، يحذف السيرفر المستخدم تلقائياً ويحدّث القائمة لبقية المستخدمين.

## 4. المفاهيم الشبكية الأساسية (Networking Concepts)

### أ. العلاقة بين WebSocket و TCP و HTTP
```text
Browser Client
   │
   │  1. HTTP Request (GET /)
   ▼
Python HTTP Server (يقدم ملفات HTML/JS)
   │
   │  2. WebSocket Handshake (Upgrade: websocket)
   ▼
TCP Connection (طبقة النقل Transport Layer)
   │
   ▼
Network (Wi-Fi / Ethernet)
   │
   ▼
Python WebSocket Server
```
- **WebSocket ليس بروتوكولاً منفصلاً عن TCP:** WebSocket يعمل في طبقة التطبيقات (Application Layer) ويستخدم **TCP** كبروتوكول نقل موثوق تحته.
- **الفرق بين HTTP و WebSocket:**
  - **HTTP:** نظام طلب/استجابة أحادي (Request/Response) غير مستمر.
  - **WebSocket:** قناة اتصال مستمرة وثنائية الاتجاه بالكامل (Full-Duplex) تسمح للسيرفر بدفع البيانات إلى المتصفح فوراً دون طلب مسبق.

---

### ب. مصافحة الـ TCP الثلاثية (TCP 3-Way Handshake)
عند فتح أي اتصال TCP (مثل اتصال WebSocket)، يقوم **نظام التشغيل (OS TCP Stack)** بإنشاء الاتصال عبر 3 خطوات:

```text
Client (Browser / OS)                         Server (Python / OS)
         │                                              │
         │  1. SYN (طلب مزامنة وفتح اتصال)             │
         ├─────────────────────────────────────────────>│
         │                                              │
         │  2. SYN-ACK (موافقة ومزامنة من السيرفر)     │
         │<─────────────────────────────────────────────┤
         │                                              │
         │  3. ACK (تأكيد استلام من العميل)            │
         ├─────────────────────────────────────────────>│
         │                                              │
         ▼                                              ▼
  [الاتصال جاهز ESTABLISHED]                      [الاتصال جاهز ESTABLISHED]
```
> **ملاحظة أكاديمية هامة:** كود Python لا ينشئ حزم SYN أو ACK يدوياً، بل يستدعي فقط دالة `connect()` أو `accept()`، ويتولى كرت الشبكة ونظام التشغيل إرسال واستقبال هذه الحزم تلقائياً.

---

### ج. إنهاء اتصال الـ TCP الرباعي (TCP 4-Way Termination)
لأن اتصال TCP ثنائي الاتجاه بالكامل، فإن إغلاقه يتطلب إنهاء كل اتجاه بشكل منفصل:

```text
Client (OS)                                   Server (OS)
         │                                              │
         │  1. FIN (العميل يطلب إغلاق اتجاه الإرسال)    │
         ├─────────────────────────────────────────────>│
         │                                              │
         │  2. ACK (السيرفر يؤكد استلام طلب الإغلاق)    │
         │<─────────────────────────────────────────────┤
         │                                              │
         │  3. FIN (السيرفر يطلب إغلاق اتجاهه أيضاً)    │
         │<─────────────────────────────────────────────┤
         │                                              │
         │  4. ACK (العميل يؤكد الإغلاق النهائي)        │
         ├─────────────────────────────────────────────>│
         │                                              │
         ▼                                              ▼
    [الاتصال مغلق CLOSED]                          [الاتصال مغلق CLOSED]
```
> **الفرق بين WebSocket Disconnect و TCP FIN:** عند الضغط على Disconnect، يرسل المتصفح أولاً حزمة `WebSocket Close Frame` على مستوى التطبيق، ثم يغلق الـ Socket الفعلي مما يحفز نظام التشغيل لإرسال حزم `TCP FIN / ACK`.

---

### د. مقارنة بين TCP و UDP

| وجه المقارنة | TCP (مثل WebSocket والمحادثة) | UDP (مثل البث المباشر والألعاب) |
| :--- | :--- | :--- |
| **طبيعة الاتصال** | متصل (Connection-Oriented) | عديم الاتصال (Connectionless) |
| **المصافحة** | يتطلب 3-Way Handshake قبل الإرسال | لا يوجد Handshake، يرسل مباشرة |
| **الموثوقية** | موثوق (يضمن الوصول والترتيب وإعادة الإرسال) | غير موثوق (قد تفقد الحزم بدون تنبيه) |
| **السرعة والتعقيد**| يحتوي على Header أكبر ومعالجة أكثر | سريع جداً وخفيف في استهلاك الشبكة |
| **الدوال المستخدمة**| `connect()`, `accept()`, `send()`, `recv()` | `bind()`, `sendto()`, `recvfrom()` |

---

### هـ. مفاهيم عناوين الشبكة (IP Addresses)
- **`127.0.0.1` / `localhost`:** عنوان الاسترجاع الذاتي (Loopback)، يرى الجهاز نفسه فقط ولا يمكن لأي جهاز خارجي على الشبكة فتحه.
- **`0.0.0.0`:** يعني "استمع على جميع كروت وواجهات الشبكة المتاحة في هذا الجهاز". نستخدمه في السيرفر لكي يستطيع الرد على الطلبات القادمة من الـ Wi-Fi والشبكة المحلية.
- **IP السيرفر في LAN (مثال: `192.168.1.10`):** العنوان المخصص لجهاز السيرفر داخل الراوتر المنزلي أو الجامعي، وهو العنوان الذي يفتحه باقي الطلاب في متصفحاتهم.

## 5. تثبيت المتطلبات (Installation)

المشروع يستخدم مكتبة خارجية واحدة فقط خفيفة للـ WebSocket، بينما يعتمد خادم الويب والتجارب على مكتبات Python القياسية.

قم بفتح منفذ الأوامر (Terminal) وثبت المكتبة:
```bash
pip install -r requirements.txt
```

---

## 6. تشغيل المشروع (Running the Server)

شغل السيرفر بالأمر التالي:
```bash
python run_server.py
```

سيظهر في الشاشة عنوان IP المحلي وروابط الدخول:
```text
============================================================
   Simple Contact — Local Network Chat Application
============================================================
[i] عنوان IP لجهازك على الشبكة المحلية: 192.168.1.15
------------------------------------------------------------
[1] لفتح التطبيق من هذا الجهاز (السيرفر):
    http://localhost:8000  أو  http://192.168.1.15:8000
------------------------------------------------------------
[2] لفتح التطبيق من أجهزة أخرى (Clients) على نفس شبكة Wi-Fi:
    http://192.168.1.15:8000
============================================================
[*] HTTP Web Server يعمل على: http://0.0.0.0:8000
[*] WebSocket Server يعمل على: ws://0.0.0.0:8765
```

## 7. خطوات الاختبار عبر 3 أجهزة (Testing with 3 PCs)

1. **تأكد أن الأجهزة الثلاثة متصلة بنفس شبكة الـ Wi-Fi / الراوتر.**
2. **جهاز السيرفر (PC 1):**
   - افتح موجه الأوامر واكتب `ipconfig` (في Windows) لمعرفة الـ IPv4 (مثلاً `192.168.1.20`).
   - شغل السيرفر: `python run_server.py`.
3. **الجهاز الثاني (PC 2 - Client 1):**
   - افتح المتصفح على: `http://192.168.1.20:8000`.
   - اكتب اسم المستخدم: `Ahmed` واضغط **Join**.
4. **الجهاز الثالث (PC 3 - Client 2):**
   - افتح المتصفح على: `http://192.168.1.20:8000`.
   - اكتب اسم المستخدم: `Mohammed` واضغط **Join**.
5. **بدء المحادثة:**
   - يضغط `Ahmed` على اسم `Mohammed` في القائمة الجانبية ويكتب رسالة.
   - تظهر الرسالة فوراً في شاشة `Mohammed` بالوقت والتاريخ.
6. **قطع الاتصال:**
   - عند ضغط أحدهما على **Disconnect**، يختفي اسمه فوراً من قائمة المتصلين لدى الطرف الآخر.

## 8. التجارب التعليمية المرفقة (Educational Demos)

يحتوي مجلد `demos/` على أمثلة مستقلة لشرح بروتوكولات الشبكات للدكتور:

### 1. تجربة TCP 3-Way Handshake:
```bash
python demos/tcp_handshake.py
```
*توضح كيف يبدأ العميل الاتصال ويتم تبادل SYN و SYN-ACK و ACK عبر نظام التشغيل.*

### 2. تجربة TCP 4-Way Termination:
```bash
python demos/tcp_termination.py
```
*توضح خطوات إغلاق اتصال الـ TCP بحزم FIN و ACK.*

### 3. تجربة سيرفر وعميل UDP:
- افتح نافذة أولى وشغل السيرفر:
  ```bash
  python demos/udp_server.py
  ```
- افتح نافذة ثانية وشغل العميل:
  ```bash
  python demos/udp_client.py
  ```
*توضح نقل البيانات بدون Handshake أو اتصال دائم.*
